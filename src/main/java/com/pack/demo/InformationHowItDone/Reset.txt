### 🧱 STEP 3: Create Reset Password Controller

```java
@GetMapping("/reset-password")
public String showResetForm(@RequestParam("token") String token, Model model) {
    Optional<ResetToken> optional = resetTokenRepository.findByToken(token);

    if (optional.isEmpty()) {
        return "expired_token"; // Show token expired page
    }

    ResetToken resetToken = optional.get();

    // Check 30 sec expiration
    if (resetToken.getCreatedAt().plusSeconds(30).isBefore(LocalDateTime.now())) {
        resetTokenRepository.deleteById(token); // Cleanup
        return "expired_token"; // Token expired
    }

    model.addAttribute("token", token); // Send token to the form
    return "confirm_password"; // The HTML form you already have
}
```

---

### 🧱 STEP 4: Handle the Password Update

```java
@PostMapping("/confirm-password")
public String confirmPassword(@RequestParam("token") String token,
                              @RequestParam("password") String newPassword) {

    Optional<ResetToken> optional = resetTokenRepository.findByToken(token);
    if (optional.isEmpty()) {
        return "expired_token";
    }

    ResetToken resetToken = optional.get();
    String email = resetToken.getEmail();

    // You must now look up the user by email and update their password
    UserModel user = userRepository.findByEmail(email);
    user.setPassword(passwordEncoder.encode(newPassword));
    userRepository.save(user);

    resetTokenRepository.deleteById(token); // Remove token after use

    return "redirect:/login?reset=success";
}
```

📌 Make sure you're using **BCrypt or another encoder** to hash the password before saving.

---

### 🧱 STEP 5: Clean Up Expired Tokens (Optional)

Using a scheduled task to clean tokens:

```java
@Scheduled(fixedRate = 60000)
public void cleanupExpiredTokens() {
    LocalDateTime cutoff = LocalDateTime.now().minusSeconds(30);
    resetTokenRepository.deleteByCreatedAtBefore(cutoff);
}
```

Add `@EnableScheduling` to your main class.

### 🔐 Security Notes

* Add CSRF protection if not already enabled.

Yes, absolutely — you **can** use a `@PathVariable` instead of a `@RequestParam` if you want to pass the token in the **URL path** instead of as a query parameter.

---

### ✅ Difference Between `@RequestParam` and `@PathVariable`:

| Type            | Example URL                    | Example Code                          |
| --------------- | ------------------------------ | ------------------------------------- |
| `@RequestParam` | `/reset-password?token=abc123` | `@RequestParam("token") String token` |
| `@PathVariable` | `/reset-password/abc123`       | `@PathVariable("token") String token` |

---

## ✅ If You Want to Use `@PathVariable`

### 1. Change your controller method:

```java
@GetMapping("/reset-password/{token}")
public String showResetForm(@PathVariable("token") String token, Model model) {
    // your logic here
    model.addAttribute("token", token);
    return "confirm_password";
}
```

---

### 2. Change the link in your email:

```java
String resetLink = "http://localhost:8080/reset-password/" + token;
```

Which produces a link like:

```
http://localhost:8080/reset-password/abc123
```

---

### ✅ Which One Should You Use?

| Use `@RequestParam` if…                          | Use `@PathVariable` if…                          |
| ------------------------------------------------ | ------------------------------------------------ |
| You want URLs like `/reset-password?token=abc`   | You prefer clean URLs like `/reset-password/abc` |
| You may want to pass multiple parameters via URL | You like REST-style design                       |

Both are valid — it's more about **URL style and preference**. Technically, both ways give you the `token` in the controller.
